# Security Policy

## Supported versions

Security fixes are provided only for the latest stable release.
Older releases, pre-releases, and unreleased development versions are not supported.
Before reporting a vulnerability, verify that it affects the latest stable release,
when practical.

## Reporting a vulnerability

Please report suspected vulnerabilities through [GitHub private vulnerability
reporting](https://github.com/luigibrosse/cbzfit/security/advisories/new).

Do not open a public issue, discussion, or pull request for an undisclosed vulnerability.
Keep the report and related details private until disclosure has been coordinated.

Include as much of the following information as possible:

- Clear reproduction steps or a minimal proof of concept
- The affected CBZFit version or commit
- The expected and observed behavior
- The potential security impact
- Suggested mitigations or fixes, if available

If sample archives or images are needed to reproduce the issue, attach only
the minimum necessary data.
Do not include credentials, secrets, personal data, or other sensitive information.

## What to expect

We aim to acknowledge a report within fourteen days. We will assess the report,
may request additional information, and will provide status updates when practical.
Remediation timing depends on the vulnerability's severity, complexity, and
release requirements.

If the report is accepted, we will coordinate the fix and public disclosure
with the reporter.
Please allow time for a supported release to be prepared before publishing
technical details. Credit will be offered when appropriate and desired.
